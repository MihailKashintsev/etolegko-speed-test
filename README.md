# HTTP Download Speed Test

Тестовое задание ETOLEGKO: консольный замер скорости загрузки на Python 3.9+.
Зависимостей нет — используется только стандартная библиотека.

## Запуск

```sh
python3 speed_test.py 'https://example.com/large-file.jpg'
# Необязательный тайм-аут сетевой операции:
python3 speed_test.py 'https://example.com/large-file.jpg' --timeout 15
```

Замените пример прямой ссылкой на достаточно большой файл. Скрипт скачает его
**10 раз**, поэтому учитывайте размер файла и стоимость трафика. Кавычки нужны,
если в адресе есть специальные символы оболочки, например `&`.

Прогресс отображается отдельной строкой после каждой полностью завершённой
загрузки: шкала из 10 сегментов, номер, байты и время. В интерактивном терминале
используются цветные акценты. При перенаправлении вывода, `TERM=dumb` или наличии
переменной `NO_COLOR` ANSI-коды отключены. Динамический спиннер не используется,
чтобы не добавлять потоки и не вмешиваться в замер.

```text
  HTTP DOWNLOAD · SPEED TEST
  10 последовательных запросов · Python stdlib
  ──────────────────────────────────────────────────────────
  ПРОГРЕСС     ЗАПРОС           ОБЪЁМ      ВРЕМЯ

  █░░░░░░░░░  01/10       100,000 байт     0.125 с
  ...
  ██████████  10/10       100,000 байт     0.125 с

  ──────────────────────────────────────────────────────────
  ЗАМЕР ЗАВЕРШЁН
  Запросов:             10/10
  Среднее время:        0.125 с
  Всего скачано:        1,000,000 байт (0.954 МиБ)
  Общее время запросов: 1.250 с
  Скорость скачивания:  0.763 МиБ/с
                        6.400 Мбит/с
```

Выше иллюстративные числа; реальные результаты зависят от адреса и соединения.

## Как работает

1. Выполняет ровно 10 последовательных GET-запросов: следующий начинается только
   после полного чтения и закрытия предыдущего ответа.
2. Читает тело блоками по 64 КиБ, не накапливая весь файл в памяти.
3. Измеряет каждый запрос монотонным `time.perf_counter()`: от начала открытия
   соединения до завершения чтения ответа. Печать прогресса в замер не входит.
4. Печатает среднее время, сумму фактически полученных байтов и скорость.

Формулы:

- среднее время = сумма длительностей / 10;
- скорость в **МиБ/с** = сумма байтов / сумма длительностей / 1 048 576;
- скорость в **Мбит/с** = сумма байтов × 8 / сумма длительностей / 1 000 000.

Используется отношение суммарного объёма к суммарному времени, а не среднее
арифметическое скоростей отдельных запросов. Объём — тело ответа без HTTP-заголовков,
TLS и прочих сетевых накладных расходов. Запрашивается `Accept-Encoding: identity`;
если сервер всё же присылает сжатое тело, считаются полученные сжатые байты.

## Ошибки и ограничения

- Допускаются только HTTP(S)-адреса без встроенных учётных данных.
- Стандартная проверка HTTPS-сертификатов включена; обычные редиректы поддерживаются.
- При HTTP/сетевой ошибке, тайм-ауте или неполном теле с `Content-Length` скрипт
  прекращает замер с кодом 1 и не выдаёт частичный результат за полный.
- Неверные аргументы: код 2. Ctrl+C: код 130. Успех: код 0.
- `--timeout` ограничивает отдельную блокирующую сетевую операцию, а не длительность
  всего запроса. Медленно поступающий поток может загружаться дольше этого значения.
- Пустые ответы допустимы: полученный объём и скорость равны нулю.
- Без `Content-Length` конец тела определяет HTTP-клиент; установить, что сервер
  собирался отправить больше данных, в общем случае невозможно.
- Это скорость скачивания с **конкретного сервера**, включая установление соединения
  и задержку ответа, а не лабораторная оценка максимальной пропускной способности
  интернет-канала. Прокси, VPN, серверный кеш и нагрузка влияют на результат.
- Скрипт учитывает стандартные настройки прокси окружения `urllib`.

## Проверки

```sh
python3 -m unittest -v
```

Тесты поднимают локальный HTTP-сервер без доступа в интернет. Проверяют десять
последовательных полных загрузок, точный объём, редирект, пустое тело, ответ без
`Content-Length`, обрыв ответа, HTTP 404, формулы, некорректные аргументы,
обработку тайм-аута и отсутствие ANSI-кодов в неинтерактивном выводе.

## Что можно улучшить

Для практического диагностического инструмента: общий deadline на запрос,
отдельные замеры DNS/TCP/TLS/TTFB и экспорт JSON. Для данного задания оставлены
фиксированные 10 последовательных запросов без параллелизма и повторных попыток,
чтобы не менять условия и не искажать измерение скрытыми ретраями.
